Step 1 of 6

GitHub Repository Initialization

MazenOS uses automated GitHub Actions to deploy the Cloudflare Worker, apply database migrations, and deploy the multi-page static Pages frontend.

  1. Create a new GitHub Repository: Go to github.com/new and create a private repository named mazenos.
  2. Unzip and Push the Source Code: Extract the provided mazenos.zip archive into a local folder, initialize git, and push to your main branch:
    Terminal 
    git init
git add .
git commit -m "feat: initial MazenOS production architecture"
git branch -M main
git remote add origin https://github.com/<your-username>/mazenos.git
git push -u origin main
  3. Confirm Repository Structure: Ensure that wrangler.toml, schema.sql, worker.js, and all tool HTML pages (index.html, taskitator.html, etc.) reside in the root directory, with .github/workflows/deploy.yml in place.
Step 2 of 6

Cloudflare Account ID & API Token

GitHub Actions requires an API token with permissions to manage D1, Workers, and Pages.

  1. Locate your Cloudflare Account ID:
    • Log in to the Cloudflare Dashboard.
    • Click on Workers & Pages in the left sidebar.
    • Your Account ID is displayed on the right sidebar. Copy this 32-character string.
  2. Generate an API Token:
    • Navigate to My Profile → API Tokens (direct link).
    • Click Create Token → Create Custom Token.
    • Name the token: MazenOS-Deploy-Token.
    • Assign the following specific permissions:
    Scope Resource Permission Level
    Account D1 Edit
    Account Workers KV Storage Edit
    Account Cloudflare Pages Edit
    Account Workers Scripts Edit
    Account Account Settings Read
  3. Store Secrets in GitHub:

    In your GitHub repository, navigate to Settings → Secrets and variables → Actions → New repository secret and add:

    Secret Name Value
    CLOUDFLARE_API_TOKEN The custom API Token string generated above
    CLOUDFLARE_ACCOUNT_ID Your 32-character Cloudflare Account ID
Step 3 of 6

Cloudflare D1 Database & KV Namespace

MazenOS centralizes all operational data in a single D1 relational SQLite database and uses Cloudflare KV for transient lock flags.

  1. Create the D1 Database: In your terminal (or Cloudflare Dashboard under Storage & Databases → D1), run:
    Terminal 
    npx wrangler d1 create mazenos_db

    Wrangler outputs your database binding snippet with a unique database_id (UUID).

  2. Create the KV Namespace: Run:
    Terminal 
    npx wrangler kv namespace create "KV"

    Wrangler outputs your KV binding snippet with a unique id.

  3. Update wrangler.toml: Paste the generated IDs into your wrangler.toml file:
    wrangler.toml 
    name = "mazenos"
main = "worker.js"
compatibility_date = "2025-02-01"

[triggers]
crons = ["0 0 * * *"] # 03:00 AM Asia/Riyadh (00:00 UTC)

[[d1_databases]]
binding = "DB"
database_name = "mazenos_db"
database_id = "PASTE-YOUR-D1-DATABASE-ID-HERE"

[[kv_namespaces]]
binding = "KV"
id = "PASTE-YOUR-KV-NAMESPACE-ID-HERE"

[vars]
TIMEZONE = "Asia/Riyadh"
DEFAULT_AI_PROVIDER = "gemini"
DEFAULT_MODEL_TIER = "light"
  4. Execute Schema Migration: Initialize the 11 empty tables in the remote database:
    Terminal 
    npx wrangler d1 execute mazenos_db --file=./schema.sql --remote
✔
All database tables start completely empty, ready for authentic inputs without synthetic sample records.
Step 4 of 6

Deployment & Domain Verification

Push your updated wrangler.toml to GitHub to trigger automated push-to-deploy, or run deployment commands directly.

  1. Trigger GitHub Action:
    Terminal 
    git add wrangler.toml
git commit -m "chore: bind production D1 database and KV namespace"
git push origin main

    Visit your GitHub repo's Actions tab to verify the workflow runs and completes all steps green.

  2. Verify Cloudflare Worker URL:

    Your Worker will be live at: https://mazenos.<your-subdomain>.workers.dev.

    Test the public hardware endpoint in your browser or curl:

    Terminal 
    curl -s https://mazenos.<your-subdomain>.workers.dev/status

    Expected initial response: {"device_unlocked": true, "reason": "All P1 milestones on track", ...}

  3. Verify Cloudflare Pages Frontend:

    Your static pages dashboard will be accessible at: https://mazenos.pages.dev.

Step 5 of 6

One-Time Universal Setup & AI Keys

Configure your unified master password, MacroDroid token, and external AI provider keys in MazenOS Universal Settings.

  1. Open Settings: Open https://mazenos.pages.dev/settings.html (or tap the gear icon in the top header).
  2. Obtain AI Provider API Keys:
    • Google Gemini: Visit Google AI Studio and create an API key (used for Light Tier gemini-2.5-flash-lite / gemini-2.0-flash-lite, Smart Tier gemini-2.5-flash, and multimodal vision proof audits).
    • Anthropic Claude: Visit the Anthropic Console and generate an API key (used for claude-3-5-haiku-latest and claude-3-5-sonnet-latest).
  3. Configure Shared Credentials: Under Universal System Settings:
    Field Description
    Active AI Provider Select Google Gemini or Anthropic Claude
    Model Tier Select Light Tier for rapid execution or Smart Tier for deep reasoning
    Gemini API Key Paste your Gemini API key (starts with AIzaSy...)
    Claude API Key Paste your Claude API key (starts with sk-ant-...)
    Daily AI Limit Daily request border (default: 50, enter 0 for unlimited). Protects API credits from burning.
    Monthly AI Limit Monthly request border (default: 1000, enter 0 for unlimited).
    MacroDroid Token Enter a custom secret string (e.g., maz_phone_99218) to authenticate phone webhooks
    Master Password Enter your master password. All web pages store this token in browser storage to authenticate API calls
  4. Save Settings: Click Save Universal Settings. The credentials persist directly in D1 system_settings.
Step 6 of 6

Android MacroDroid Hardware Automation

MacroDroid enforces physical discipline by polling the hardware lock status, forwarding bank SMS messages, and auditing study video streaming.

Macro 1: Periodic Hardware Lock Poller

Polls /status every 10 minutes. If an overdue P1 task exists outside rest windows, raises a persistent lock screen overlay.

  • Trigger: Regular Interval → Every 10 Minutes.
  • Action 1: HTTP Request → GET https://mazenos.<your-subdomain>.workers.dev/status.
  • Action 2: JSON Parse → Extract device_unlocked into string variable [lv=unlocked].
  • Action 3: If [lv=unlocked] == "false":
    • Lock Screen (or Display Dialog / Fullscreen Overlay with text: "MazenOS: Overdue Priority 1 Task. Return to desk.").
  • Action 4: Else: Dismiss lock overlay.
ℹ
Automatic Suspensions: The /status endpoint automatically returns device_unlocked: true during the Riyadh daily rest window (12:30 - 13:15), all day on Fridays (Friday Builder Safeguard), and whenever Sickness Mode is active.

Macro 2: Bank SMS Auto-Ledger Forwarder

Intercepts bank transaction SMS notifications and posts them to the zero-cost regex parser endpoint.

  • Trigger: SMS Received → From: *AlRajhi*, *SNB*, *Riyad*, *STCPay*, or *mada*.
  • Action: HTTP Request:
    • Method: POST
    • URL: https://mazenos.<your-subdomain>.workers.dev/api/budget/sms
    • Header 1: Content-Type: application/json
    • Header 2: Authorization: Bearer <YOUR_MACRODROID_TOKEN>
    • Body: {"sms_text": "{sms_message}"}
  • Result: Amount in SAR, card source, merchant name, and balance are extracted at zero token cost and logged in budget_entries.

Macro 3: NewPipe Media Audit

Whenever NewPipe plays video content, Ari audits the title against the active task or curriculum unit.

  • Trigger: Notification Received → App: NewPipe.
  • Action: HTTP Request → POST /api/audit/media with body {"video_title": "{notification_title}"} and Bearer token header.
  • Action: If response allowed == false, send Home button intent and raise warning banner.
